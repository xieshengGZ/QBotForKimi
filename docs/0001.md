0. 决策速览

项目 决策

1. 目标

- 在电脑终端之外，用手机主 QQ 私聊控制同一台机器上的 kimico 交互式进程。
- 两个入口共享同一个 kimico 进程与内存上下文：电脑操作一半，手机可接续。
- 本地终端体验与直接运行 kimico 完全一致。
- 长任务在 tmux 后台持续运行，不受终端关闭、QQ 离线影响。

2. 非目标

- 不修改 kimico 源码，不改其原生 IO。
- 不做多会话池；Kimi 侧会话切换由用户发送 /session，网关原样转发。
- 仅文本私聊；不支持群聊、图片、文件、语音。
- 不做云端会话、Web 管理台、跨机调度。
- #code（调用 Kimi Code API）为 P2，不进入本期。
- 本网关不是 Kimi Code Skill。

3. 运行模型

- 单机、单实例、单 tmux 会话，名称固定 kimico；会话内只跑一个 kimico 进程。
- kimico 直接作为 pane 的启动命令运行，不经过交互式 shell。
- tmux 设置 remain-on-exit on：kimico 退出后 pane 保留为 dead 状态，便于检测与原地重启。
- 两个输入入口：本地终端 attach；手机 QQ 私聊经 NapCat → 网关。
- 网关是唯一向 kimico 注入输入的组件；本地终端由 tmux 直接接管。
- 输出固定渲染到本地终端；mirror=on 时网关额外把稳定新增文本推送到 QQ。

4. 消息路由与控制指令

前缀 # 开头为控制指令，仅网关处理，不转发给 kimico。命令名不区分大小写，首尾空白忽略。

指令 行为
#mirror on 开启手机端 kimico 输出推送。
#mirror off 关闭推送，同时清空待发送队列。
#status 回复：tmux 会话是否存活、kimico 是否存活、mirror 状态、入站队列长度、出站队列长度、最后输出时间、网关运行时长。
#clear 清空本地输出缓存与待发送队列，并把输出基线重置到当前屏幕；不影响 kimico 上下文。
未知 # 指令 回复用法提示，不转发。

- 控制指令回执始终发送，不受 mirror 影响。
- 空消息忽略，不回复。
- 其余消息（包括 /session）原样进入输入队列，网关不解析、不改写。

5. 输入通道

- 校验：仅接受 post_type=message、message_type=private、user_id=主QQ 的事件；其他静默丢弃。
- 去重：message_id 保留最近 200 条，重复上报直接丢弃。
- 取文本：拼接 message 数组中 type=text 的片段；没有文本片段时回复“仅支持文本消息”。
- 入站队列：FIFO，容量 50；满时回复“当前繁忙，请稍后重试”并丢弃新消息。
- 消费：单个工作线程串行取出并注入，保证注入动作不交错。
- 注入方式：tmux set-buffer → paste-buffer -p → send-keys C-m，支持多行文本，避免 shell 转义问题。
- 不做“回答结束”检测；连续消息按到达顺序依次进入 kimico。
- 同一时刻只由一方输入，由操作人员保证；网关不检测本地输入状态。
- 普通消息注入成功不回复 ACK；注入失败回复错误提示并记录日志。

6. 输出通道

- tmux 创建会话时设置 history-limit 50000。
- 每 300ms 执行：tmux capture-pane -p -J -S -5000 -t kimico。
- 差分：把本次行列表与上次快照做尾部/头部重叠匹配，重叠之后的行视为新增；无法匹配时重建基线并丢弃该片段，记录 warning。
- 稳定判定：新增行连续 3 次轮询保持不变才视为稳定；最后一条非空行延迟确认，避免把进度条中间态推出去。
- 过滤：空行；可配置正则（提示符、状态栏等）；刚注入消息的回显（文本归一化后 10 秒内只跳过一次）。
- mirror=on：稳定新增行按 1500 字符切段入发送队列；超长单行硬切；段间发送间隔 1s。
- mirror=off：不进入发送队列，但基线继续推进；重新开启后不回放旧内容。
- 发送队列容量 500；溢出时丢弃最旧内容并发送一次“输出过快，部分内容未推送”提示。
- 发送线程：urllib.request 调用 NapCat HTTP API，超时 3s；失败等待 2s 重试一次，仍失败则记录日志并丢弃该段。

7. 进程生命周期与恢复

- systemd 托管网关，Restart=always；tmux server 与 kimico 独立于网关存活。
- 启动自检：tmux 会话不存在则创建（设置 history-limit 并直接启动 kimico）；存在则接管。
- 存活检测：tmux display-message -p -t kimico '#{pane_dead}'，0 为存活，1 为退出。
- 恢复：pane dead 后等待退避 5s / 15s / 60s，执行 tmux respawn-pane -k -t kimico <kimico_command>。
- 10 分钟内连续 3 次恢复失败：停止重试，发送 QQ 告警；网关重启后计数清零。
- 每次重启尝试发送一条 QQ 通知；kimico 连续运行超过 60 秒后失败计数清零。
- 重启会丢失 kimico 内存上下文，属预期。
- 网关自身重启：mirror 从状态文件恢复；输出基线重置到当前屏幕，不回放历史内容。

8. QQ 接入

- 协议端：NapCat（无头 NTQQ），Docker 部署，使用 --network host，使容器内可直接访问 127.0.0.1。
- OneBot v11 HTTP POST 上报到 http://127.0.0.1:8080/cq。
- 网关发送消息：POST 到 NapCat HTTP API（默认 http://127.0.0.1:3000），调用 send_private_msg。
- 鉴权：请求头 Authorization: Bearer <access_token>，网关校验失败返回 401。
- 仅放行主 QQ 的私聊文本；其他发送人、群消息静默丢弃。
- NapCat 重试可能产生重复事件，由 message_id 去重兜底。

9. 技术栈与进程结构

- Python 3.12，仅标准库：http.server.ThreadingHTTPServer、queue.Queue、threading、subprocess、urllib.request、tomllib、json、logging、signal。
- 运行时零第三方依赖；pytest 仅作为开发依赖。
- 单进程四类线程：
  1. HTTP 接入线程（ThreadingHTTPServer，每个请求一个线程）；
  2. 入站工作线程（消费消息队列，执行指令或注入）；
  3. 监控线程（存活检测 + 输出轮询 + 差分）；
  4. 出站发送线程（限速调用 OneBot API）。
- 共享状态用 threading.Lock 保护：mirror、输出基线、队列、最后输出时间。
- 模块划分：
  - config.py：TOML 加载与校验
  - state.py：状态文件读写
  - onebot.py：HTTP 收发与鉴权
  - router.py：指令解析与回执
  - input.py：队列与 tmux 注入
  - capture.py：capture-pane 读取、差分、稳定判定
  - mirror.py：过滤、切段、发送队列
  - session.py：tmux 会话创建、存活检测、重启
  - __main__.py：启动与线程编排

11. 状态文件（state.json）

{
  "mirror": false
}

- 仅持久化 mirror；输出基线不持久化，重启后重置到当前屏幕。
- 写入采用临时文件 + os.replace，保证原子性。

12. 验收口径

1. 本地 attach 输入，手机 mirror on 时能看到该回答；mirror off 时手机不收 kimico 输出，但仍收到控制回执。
2. 手机发送普通消息，本地终端实时看到注入与回答；mirror on 时回答分段回到手机。
3. 手机连续发送两条消息，注入顺序与发送顺序一致，不出现两段文字拼接。
4. #status 返回会话存活、kimico 存活、mirror、两个队列长度、最后输出时间、运行时长。
5. #clear 后旧缓存不再推送，kimico 上下文不受影响。
6. 长回答按 1500 字符切段，段间隔不小于 1s，顺序正确。
7. 非主 QQ、群消息被静默忽略；非文本消息收到固定提示。
8. 手动 kill kimico，网关按退避自动重启并发送 QQ 通知；连续 3 次失败后停止并告警。
9. 网关重启后 mirror 状态恢复，且不回放重启前的输出。
10. 本地 tmux attach 的显示与直接运行 kimico 一致，仅多出网关注入的输入。

13. 已知限制

- 轮询 + 稳定判定带来约 1 秒级延迟。
- kimico 崩溃重启后内存上下文丢失。
- 回显过滤依赖可配置正则，kimico 改版后可能需要调整。
- QQ 侧存在风控与发送频率限制，网关只做保守限速。
- 单实例单会话，不支持多机统一调度。

14. 构建顺序

1. config / state / logging
2. session：tmux 创建、pane_dead 检测、respawn
3. input：队列、文本提取、粘贴注入
4. capture / mirror：轮询、差分、稳定判定、切段、发送
5. onebot：HTTP 接入、鉴权、发送 API
6. router：指令解析与回执
7. recovery：退避重启与告警
8. 测试、systemd 单元、部署手册
